# AI 像素游戏素材生成平台技术路线

## 1. 文档目的

本文档定义一套可实施的 AI 像素游戏素材生成平台技术路线。平台面向角色、物品、地图和场景素材，支持提示词生成、参考图生成、多方向与动作变体、素材标准化，以及在临时游戏环境中进行移动、碰撞和交互审查。

本文档只保留当前具备实施条件的方案，并以可逐步交付、可验证、可扩展为原则。

---

## 2. 产品定位

平台不是一个单纯的生图界面，而是一套完整的游戏素材生产系统：

> 结构化素材需求 → AI 生成 → 自动审查 → 定向修复 → 素材标准化 → 游戏内实测 → 人工终审

最终目标是减少从概念设计到游戏可用素材之间的人工整理工作，而不是依赖单次模型调用直接得到完美成品。

### 核心能力

1. 用户通过提示词创建角色、物品、地图和场景素材。
2. 用户上传参考图后，生成同一角色或物品的方向、动作和样式变体。
3. 将 AI 输出自动处理为尺寸、色板、透明通道和锚点统一的游戏素材。
4. 将角色、地图和道具加载到审查场景中，执行移动、碰撞、遮挡和交互测试。
5. Agent 根据检查结果进行有限次数的局部修复或重新生成。
6. 保存全部生成版本、审查结果和最终通过版本。

---

## 3. 总体技术路线

平台采用“C++ 主程序 + 可替换 AI 生成服务 + Godot 审查运行时”的混合架构。

### 数据流

1. 用户在 C++ 创作工作台中输入提示词、上传参考图并选择素材规格。
2. 主程序生成结构化的素材规格 AssetSpec。
3. 任务编排器根据任务类型选择云端模型或本地 ComfyUI 服务。
4. AI 服务返回一组候选图片及生成元数据。
5. C++ 素材工厂执行透明边清理、像素化、调色、裁切、对齐和图集打包。
6. 审查 Agent 依次执行程序检查、视觉检查和游戏沙盒测试。
7. 不合格素材进入局部修复或定向重新生成流程。
8. 合格素材进入人工终审并导出为引擎无关资产包。

### 核心边界

- AI 模型负责创意生成和局部修复。
- C++ 素材工厂负责把图片转换为规范的游戏素材。
- Agent 负责流程编排、检查、诊断和有限重试。
- Godot 审查器负责验证素材在实际游戏环境中的可用性。
- 用户负责最终审美判断和版本确认。

## 4. 推荐技术栈

| 模块 | 推荐技术 | 用途 |
|---|---|---|
| 桌面主程序 | C++20、Qt 6 | 创作界面、项目管理、素材库、任务进度 |
| 项目构建 | CMake、vcpkg、Visual Studio 2022 | 跨模块构建和依赖管理 |
| 图像处理 | OpenCV、libpng | 裁切、抠图、缩放、颜色量化、边缘处理 |
| 网络通信 | Qt Network 或 libcurl | 调用云端模型和本地推理服务 |
| 数据序列化 | nlohmann/json | AssetSpec、任务、审查报告和导出清单 |
| MVP 数据库 | SQLite | 本地项目、任务、版本和审查结果 |
| 文件存储 | 项目目录文件系统 | 原图、候选图、图集、地图和缩略图 |
| 本地 AI 服务 | ComfyUI | 多方向、姿态控制、LoRA 和批量工作流 |
| 审查运行时 | Godot 4 | 移动、碰撞、遮挡、灯光和交互测试 |
| C++ 扩展 | Godot GDExtension | 需要时实现高性能或共享逻辑模块 |
| 进程通信 | WebSocket、本地 HTTP 或本地 IPC | Qt、ComfyUI 与 Godot 之间传递任务和状态 |

正式云端版本可将 SQLite 升级为 PostgreSQL，并将本地文件存储升级为 S3 兼容对象存储，但不影响核心模块接口。

## 5. C++ 主程序模块

### 5.1 项目与风格包

每个项目保存以下内容：

- 项目名称和目标引擎。
- 原创风格包和调色板。
- 默认像素尺寸、世界比例和光照方向。
- 角色、物品、地图和场景素材列表。
- 生成模型、工作流和参数版本。
- 审查记录和最终通过版本。

风格包用于约束同一项目中的轮廓、配色、光照、透视角度和像素密度。

### 5.2 素材规格 AssetSpec

每个生成任务必须先形成结构化规格，至少包括：

- 素材类型：角色、物品、地图、建筑或场景。
- 提示词、排除项和参考图。
- 输出方向和动作。
- 单帧尺寸、图集布局和透明背景要求。
- 调色板、像素密度和缩放规则。
- 角色脚底锚点或物品交互点。
- 光照方向和透视方式。
- 碰撞、遮挡和导航需求。
- 模型、工作流、随机种子和版本信息。
- 自动审查阈值和重试预算。

AssetSpec 是生成、检查、修复和导出的统一依据。

### 5.3 任务编排器

任务编排器负责：

- 拆分角色方向、动作和地图层级任务。
- 选择云端或本地模型适配器。
- 控制并发、取消、暂停和恢复。
- 跟踪生成进度和费用。
- 保存每一次输入、输出和审查结果。
- 对失败任务执行有限重试。
- 保留历史最佳版本，避免被新结果覆盖。

第一版应采用可控状态机实现，不使用不可预测的自由运行 Agent。

### 5.4 模型适配层

C++ 主程序只依赖统一的生成接口，不直接依赖某一家模型供应商。

统一能力包括：

- 文生图。
- 单张或多张参考图编辑。
- 局部遮罩重绘。
- 透明背景输出。
- 姿态、深度和边缘条件输入。
- 任务状态查询和取消。
- 图片、种子、参数和费用信息返回。

模型适配器分为：

- 云端模型适配器：用于高质量母版、概念图和小批量生成。
- ComfyUI 适配器：用于多方向、动作、ControlNet、LoRA 和批量受控生成。

## 6. AI 生成执行策略

### 6.1 第一阶段：云端 API 为主

MVP 首先接入一个支持提示词、参考图编辑和透明背景的云端模型，快速完成端到端业务验证。

云端主要承担：

- 角色初始母版。
- 用户参考图的设计转换。
- 道具和图标。
- 建筑、场景和地图概念图。
- 少量高质量局部重绘。

模型密钥不得硬编码在客户端。个人版本可将用户自己的密钥保存在 Windows 凭据管理器中；平台版本应由自有服务端保存密钥并进行额度、计费和访问控制。

### 6.2 第二阶段：加入本地 ComfyUI

ComfyUI 作为独立本地 GPU 服务运行，由开发者预先配置和保存工作流。普通用户只操作 C++ 工作台，不直接操作节点界面。

本地工作流主要承担：

- 角色四方向或八方向生成。
- 待机、行走、攻击和交互动作。
- 姿态骨架、深度、边缘和轮廓控制。
- 项目专属 LoRA。
- 大批量变体和重复生成。
- 隐私图片的本地处理。

C++ 程序负责替换工作流中的提示词、参考图、姿态图、随机种子和输出目录，并接收执行进度和结果。

### 6.3 最终自动路由

默认采用以下分配规则：

- 概念探索和高质量母版优先云端。
- 多方向、动作、批量和专属 LoRA 优先本地。
- 本地服务不可用时回退到云端支持的能力。
- 隐私素材优先本地。
- 用户可手动选择自动、云端或本地模式。

推荐角色生产方式为：云端生成并确认母版，本地受控生成方向和动作，C++ 完成标准化与图集打包。

## 7. 闭环素材 Agent

### 7.1 初始生成

每个任务生成多个候选，分别保存模型、参数、种子、参考图和工作流版本。Agent 不直接覆盖旧版本，而是在候选中持续维护当前最佳结果。

### 7.2 确定性程序检查

由 C++ 完成以下硬性检查：

- 图片和单帧尺寸。
- 透明通道和透明边缘。
- 内容是否越界。
- 像素网格和缩放倍率。
- 调色板及颜色数量。
- 方向、动作和帧是否齐全。
- 角色脚底锚点是否对齐。
- Sprite Sheet 排布是否正确。
- 地图图块边缘是否存在明显接缝。

可通过程序修复的问题直接修复，不调用生图模型。

### 7.3 独立视觉审查

使用独立视觉模型对候选素材、参考图、角色母版和 AssetSpec 进行比较，输出结构化 ReviewReport：

- 身份、脸型、发型和服装一致性。
- 武器、饰品和关键特征是否缺失。
- 身高、头身比和轮廓一致性。
- 方向、姿态和动作是否正确。
- 风格、配色和光照是否统一。
- 是否存在畸形、重复部件或明显伪影。
- 问题区域、严重程度和建议处理方式。

视觉审查模型与生图模型相互独立，避免完全依赖模型自我评价。

### 7.4 游戏沙盒测试

Godot 审查器读取资产包和场景清单，自动执行：

- 四方向移动和动画播放。
- 墙体、地形和道具碰撞。
- 前景遮挡和绘制顺序。
- 拾取、开箱、开门和触发器交互。
- 不同灯光、相机角度和像素缩放下的显示检查。
- 自动截图、状态记录和错误日志收集。

测试结果返回任务编排器，参与最终评分。

### 7.5 定向修复

Agent 根据问题类型选择处理方式：

- 尺寸、色板、透明边和锚点问题由 C++ 修复。
- 局部配饰、脸部或武器错误使用遮罩重绘。
- 单个方向错误只重新生成该方向。
- 单个动画帧错误只重新生成该帧。
- 身份整体漂移时回到确认过的母版重新生成。
- 地图可达性问题修改逻辑层，不通过重画整张图解决。

### 7.6 停止条件

每个任务必须配置：

- 最大生成轮次。
- 最大费用和最长等待时间。
- 最低合格分数。
- 最低改进幅度。
- 连续无改进停止条件。
- 必须人工确认的风险项。

达到合格标准后进入人工终审；达到预算或轮次限制后提交当前最佳版本和未解决问题。

## 8. 素材生产管线

### 8.1 角色素材

1. 输入提示词或人物参考图。
2. 清理背景并提取人物主要特征。
3. 生成多个高质量角色母版。
4. 用户选定唯一身份母版。
5. 锁定脸、发型、服装、配色和装备描述。
6. 通过方向模板、姿态骨架、深度或轮廓条件生成不同方向。
7. 生成待机和行走基础动作。
8. 执行透明边、像素网格、调色板和脚底锚点处理。
9. 打包 Sprite Sheet 和动画元数据。
10. 放入沙盒执行移动、遮挡和碰撞测试。

MVP 先支持四方向、待机和行走，之后扩展八方向和其他动作。

### 8.2 物品素材

1. 根据类别、用途、材质、尺寸等级和风格包生成候选。
2. 统一透视角度、光照方向和背景透明度。
3. 执行尺寸、轮廓、调色板和边缘处理。
4. 设置碰撞区域、拾取点和交互类型。
5. 在场景中验证比例、遮挡和交互动画。

角色装备、家具、建筑部件和 UI 图标使用不同规格模板。

### 8.3 地图素材

地图采用“逻辑先行、视觉分层”的生成方式：

1. 定义地图尺寸、房间关系、道路、入口和出口。
2. 生成语义网格和可行走区域。
3. 根据语义网格选择或生成地面、墙体和装饰图块。
4. 分离地面层、墙体层、装饰层和前景遮挡层。
5. 生成碰撞、导航、出生点和交互点数据。
6. 在 Godot 中自动运行寻路、碰撞和交互测试。
7. 对视觉问题重新生成局部图块，对逻辑问题修改地图数据。

AI 场景图用于确定美术方向，不直接作为完整可玩地图。

## 9. 像素素材标准化

AI 原始输出统一进入 C++ 素材工厂：

1. 保存原图，不覆盖和删除生成结果。
2. 自动识别主体并裁切画布。
3. 清理透明边缘和残留背景。
4. 统一到项目规定的像素网格。
5. 使用最近邻算法缩放。
6. 根据项目色板执行颜色量化。
7. 根据风格配置选择是否使用抖动。
8. 检查轮廓在实际显示尺寸下是否清晰。
9. 设置锚点、碰撞区域和交互点。
10. 输出图集、单图和引擎无关元数据。

建议先生成较高分辨率母版，再转换到目标像素尺寸，避免直接生成极低分辨率图片造成结构不稳定。

## 10. Godot 审查平台

Godot 审查器作为独立预览程序运行，与 Qt 主程序通过场景清单和本地通信接口连接。

### 审查功能

- 加载角色 Sprite Sheet、地图和道具。
- 热加载新版本素材。
- WASD 移动和方向切换。
- 待机、行走和交互动画播放。
- 碰撞、导航和前景遮挡测试。
- 拾取、开箱、开门和触发器模板。
- 灯光、阴影、景深、雾效和相机角度切换。
- 自动截图和运行日志输出。
- 人工标记通过、退回和问题区域。

审查器只执行白名单交互模板和结构化场景数据，不执行 AI 生成的任意代码。

## 11. 资产格式

### 角色资产包

- 原始母版图片。
- 各方向、动作和单帧 PNG。
- Sprite Sheet PNG。
- 动画、帧率、方向和锚点 JSON。
- 碰撞区域和遮挡高度。
- 模型、种子和工作流版本。
- 审查报告和通过状态。

### 物品资产包

- 透明 PNG。
- 类型、尺寸等级和交互类型。
- 锚点、碰撞区域和拾取点。
- 变体和升级版本关系。
- 审查报告和通过状态。

### 地图资产包

- TileSet 图集。
- 语义网格和地图布局。
- 地面、墙体、装饰和遮挡层。
- 碰撞、导航、出生点和交互点。
- 灯光和场景配置。
- 审查报告和通过状态。

导出格式优先保持引擎无关，再由导出器转换为 Godot 或其他目标引擎格式。

## 12. 核心数据对象

- Project：项目和全局配置。
- StylePack：风格、调色板、透视和光照约束。
- AssetSpec：单个素材的结构化需求。
- Asset：素材逻辑对象。
- AssetVariant：候选、方向、动作和版本。
- GenerationJob：生成任务及执行状态。
- PipelineRun：一次完整流水线执行记录。
- ReviewReport：程序、视觉和运行时审查结果。
- PreviewScene：审查场景及素材引用。
- ExportPackage：最终通过的导出资产包。

所有对象使用稳定 ID 关联，文件路径不作为唯一身份。

- 确定性检查、视觉审查和有限修复闭环。

## 14. 实施阶段

### 阶段 0：能力验证

使用固定角色、固定道具和固定小地图验证：

- 参考图编辑质量。
- 四方向身份一致性。
- 透明背景质量。
- 像素化与色板效果。
- 单次成本、延迟和失败率。
- 局部重绘有效性。

输出模型能力基准和默认参数。

### 阶段 1：端到端 MVP

完成：

- Qt 项目和素材工作台。
- AssetSpec 和本地项目存储。
- 云端模型适配器。
- 角色、物品和模板地图基础管线。
- C++ 素材标准化。
- Godot 审查场景。
- 人工选择、通过和退回。

### 阶段 2：闭环 Agent

完成：

- 程序化硬性检查。
- 独立视觉审查。
- 结构化问题报告。
- 局部遮罩修复。
- 单方向和单帧重试。
- 费用、轮次和停止条件。

### 阶段 3：本地受控生成

完成：

- ComfyUI 服务适配器。
- 姿态、深度和边缘控制工作流。
- 项目专属 LoRA 支持。
- 云端与本地自动路由。
- 批量方向和动作生成。

## 15. MVP 验收标准

### 功能验收

- 用户可以通过提示词生成角色、道具和场景素材。
- 用户可以上传参考图并创建角色母版。
- 系统可以生成并保存角色四方向素材。
- 系统可以执行透明边、像素化、色板和锚点处理。
- 系统可以导出 Sprite Sheet 和结构化元数据。
- 用户可以把角色、地图和道具加入审查场景。
- 角色可以移动、碰撞、被遮挡并与道具交互。
- 系统可以保存每次生成和审查版本。
- Agent 可以识别硬性错误并对局部问题有限重试。

### 质量验收

- 所有帧尺寸和锚点符合 AssetSpec。
- 素材透明边缘无明显残留背景。
- 四方向角色保留母版的主要身份、服装和配色特征。
- 动画播放时不存在明显画布跳动。
- 地图出生点到目标交互点可达。
- 碰撞和前景遮挡符合场景配置。
- 未达到自动标准的结果会进入人工终审，不会被标记为已完成。

### 工程验收

- 更换云端模型只需新增或修改适配器。
- ComfyUI 未安装时不影响云端模式运行。
- 原始图片、候选和通过版本均可追溯。
- API 密钥不写入源代码和导出资产。
- 任务失败、超时、取消和额度不足均有明确状态。

## 16. 关键风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 角色方向身份漂移 | 唯一母版、多参考约束、方向模板、独立视觉审查、局部修复 |
| 动画帧抖动 | 姿态模板、脚底锚点对齐、轮廓比较、单帧重试 |
| 伪像素和颜色混乱 | 高分辨率母版、最近邻缩放、固定色板、颜色量化 |
| 地图美观但不可玩 | 逻辑先行、语义网格、碰撞导航测试、视觉与逻辑分层 |
| Agent 无限重试 | 最大轮次、费用预算、最低改进阈值、连续无改进停止 |
| 云端费用和服务波动 | 任务缓存、候选数量限制、能力路由、本地 ComfyUI 补充 |
| API 密钥泄露 | Windows 凭据管理器或自有服务端保存，不硬编码客户端 |
| 模型和工作流变更 | 保存模型、参数、种子、工作流版本和生成元数据 |
| 用户图片隐私 | 明确云端上传提示，支持本地处理模式和可配置保存策略 |
| 素材版权和风格风险 | 使用用户授权素材和原创风格包，记录来源及生成信息 |

## 17. 最终路线结论

项目采用以下确定技术路线：

1. 以 C++20、Qt 6、CMake 和 OpenCV 构建桌面主程序和素材工厂。
2. 使用统一模型适配层隔离云端 API 与本地 ComfyUI。
3. MVP 先接入云端模型，完成角色、物品、地图和审查场景的端到端闭环。
4. 角色先生成并确认唯一母版，再生成四方向和基础动作。
5. 地图采用逻辑先行和视觉分层，不将场景图直接作为可玩地图。
6. 使用确定性检查、独立视觉审查和 Godot 沙盒实测构成闭环 Agent。
7. 修复以局部重绘和程序处理为主，并设置明确的预算与停止条件。
8. Godot 作为独立审查运行时，通过结构化清单与 Qt 主程序通信。
9. 所有素材保留原图、候选、审查和最终版本，支持追溯和回滚。
10. 第二阶段加入 ComfyUI 的姿态、深度、ControlNet、LoRA 和批量工作流。

这条路线可以先快速验证产品价值，再逐步提高一致性、可控性和本地化能力，同时保持模型供应商和目标游戏引擎的可替换性。
